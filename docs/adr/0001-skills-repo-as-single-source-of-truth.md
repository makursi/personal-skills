# 仓库是 Skill 的唯一真源

第三方 Skill 由外部管理器按 lock 安装，我自己的 Skill 散落在各项目的 `.agents/skills` 里，没有任何位置称得上定义。定义散落就会生多份副本，改动无法收敛。因此决定：`skills/` 是唯一真源，Skill 只在这里编写，再单向安装到消费目录，反向复制回来不成立。

## Considered Options

- **归档镜像**：日常仍在消费目录里改，仓库定期同步。否决理由：双向同步必然冲突，冲突时无法判断哪边是对的。
- **精选库**：只收整理过的部分，其余留在本地。否决理由：要持续判断“哪些算仓库内容”，最终退化成镜像。

## Consequences

- 改 Skill 必须先改仓库，再装到消费目录。消费目录里的副本不再可编辑。
- 新机器初始化多一步：clone 仓库后运行安装脚本。
